# Задача 2: сегментація дорога / рослинність / перешкода (3 класи) + авто-розмітка

Продовження `road_seg` (бінарна дорога) під **нову метрику організаторів** (`seg_test/eval.py`, 23.10):

- класи: **дорога** (RGB 255,0,255), **рослинність** (0,255,255), **перешкода** (255,255,0);
  небо (0,0,255) і чорне (не розмічено) **не оцінюються**;
- здаємо 1-канальні PNG з індексами `1 дорога, 2 рослинність, 3 перешкода` у папку `inference/`
  поруч із `frames/` і `markdown/`; розмір = розмір кадру;
- метрика: для кожного кадру IoU кожного класу (лише на розмічених пікселях), середнє по класах,
  потім середнє по кадрах (**per-image mIoU**). Окремо рахується для всіх кадрів (`ALL`) і для
  ручних (`MANUAL` — номер кадру закінчується на `00`; решта — автопропагація розмітки).

Нюанс метрики: якщо в кадрі **немає** перешкод, а модель намалювала хоч один піксель — IoU перешкоди = 0
і mIoU кадру падає на третину. Тому постобробка класу «перешкода» важить більше за архітектуру.

## Скрипти

| Файл | Що робить |
|---|---|
| `prep_multiclass.py` | кольорові маски організаторів → індекси `0 небо, 1 дорога, 2 росл, 3 переш, 255 ігнор`; формат `images/<seq>__<кадр>.jpg`, `masks/<seq>__<кадр>.png` |
| `train_mc.py` | навчання (smp: Unet / FPN / Segformer / UPerNet…, 4 виходи), CE + Dice, валідація **за офіційною метрикою** (argmax лише серед 1..3). `--extra-binary` — бінарні маски дороги з `label_tool.py` як часткова розмітка «дорога / не дорога» |
| `predict_mc.py` | пише `inference/*.png` для всіх `frames/` у папці; опції `--tta --smooth --obstacle-scale --min-obstacle --keep-tall --models` (ансамбль) |
| `tune_post.py` | перебір постобробки за офіційною метрикою (рахує ймовірності один раз) |
| `autolabel.py` | **авто-розмітка**: відео/кадри → наш формат + (`--package`) папки `frames/ markdown/` у кольорах організаторів + `conf.csv` (частка впевнених пікселів на кадр — що перевіряти людині першим) + (`--vis`) відео з маскою |

## Швидкий старт

```bash
source /data/venvs/hack/bin/activate && cd ~/hacaton/def_hacaton/road_seg

# 1. дані
python prep_multiclass.py /data/seg_new/seg_dev_extended --out /data/seg_mc/train
python prep_multiclass.py /data/seg_new/test/seg_test     --out /data/seg_mc/val

# 2. навчання (RTX 2060: MobileNetV2 512x288 ≈ 20 с/епоха, 704x352 ≈ 35 с; EfficientNet-B4 704x352 ≈ 65 с)
python train_mc.py --arch Unet --encoder mobilenet_v2 --size 704 352 --batch 8 --epochs 25 \
    --extra-binary /data/road_seg/data --out /data/seg_mc/runs/mc.pt --log /data/seg_mc/runs/mc.log

# 3. підбір постобробки
python tune_post.py --models /data/seg_mc/runs/mc.pt --root /data/seg_new/test/seg_test

# 4. прогноз у форматі організаторів + їхній скорер
python predict_mc.py /data/seg_new/test/seg_test --models /data/seg_mc/runs/mc.pt \
    --smooth 0.5 --obstacle-scale 0.4 --min-obstacle 3000 --keep-tall 0.3
(cd /data/seg_new/test/seg_test && python eval.py)

# 5. авто-розмітка нового відео (пакет для правки людиною + псевдорозмітка для донавчання)
python autolabel.py відео.mp4 --models /data/seg_mc/runs/mc.pt --out /data/seg_mc/pseudo --every 60 --step 6 --package --vis
```

## Що з'ясували

- Бінарна модель дороги + «все інше = рослинність» уже дає 0.73: рослинність домінує серед не-дороги.
- Клас «перешкода» — головне джерело втрат. У навчальних послідовностях перешкоди є на 86–93 % кадрів
  (медіана 2–10 тис. px), у тестових seq3 — на 45 % і дрібні (медіана 700 px), seq5 — жодної.
  Модель переносить звичку «перешкода майже завжди є» → хибні перешкоди на лінії дерев.
  Ліки: множник ймовірності перешкоди (0.4), мінімальна площа плями (3000 px), згладжування в часі (0.5),
  виняток для вузьких високих плям (стовпи, `--keep-tall 0.3`).
- Згладжування ймовірностей у часі допомагає всім класам: розмітка організаторів між ручними кадрами теж
  автопропагована, тобто гладка в часі.
- seq5 (трав'яниста колія): розмітник вважає її дорогою, модель — рослинністю (IoU дороги 0.56–0.70). Це стиль
  розмітки, його можна вивчити лише з таких прикладів.
- Великий енкодер (EfficientNet-B4) на 3 навчальних послідовностях перенавчається (loss удвічі менший, mIoU
  гірший за MobileNetV2) — різноманітність даних важливіша за розмір моделі. Звідси псевдорозмітка 18 відео.
